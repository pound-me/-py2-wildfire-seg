# 轻量化硬约束预算制修订提案（已被正式规则取代）

日期：2026-07-26
状态：**历史提案。用户已于2026-07-26批准新的实测实时预算并正式启动C路线。**

正式生效规则见`docs/ROUTE_C_ACTIVATION_AND_REALTIME_BUDGET_2026-07-26.md`及
`docs/EXPERIMENT_RULE_AMENDMENTS.md` Amendment 4。新规则不采用本提案原先建议的固定
`FLOPs <= +5%`上限，而是以RTX 2060同会话成对测速达到至少30 FPS为硬门槛；参数量与
FLOPs继续完整报告并进入Pareto比较。

## 1. 提案动机

当前“部署参数量和FLOPs均不得高于Fusion基线”的零增量规则能够保证严格轻量，但也会
在训练前排除只增加极少计算、却可能显著改善RGB+IR融合的机制。DySample Context曾因
参数+0.8663%、FLOPs约+0.0718%而被规则拒绝，这说明零增量条件已经开始限制可研究的
融合方法，而不是单纯过滤重模型。

## 2. 建议新规则

仅在导师和用户书面批准后，把结构候选的工程门槛改为：

1. 以四通道Fusion PIDNet-S为基线，在同一256×256输入和同一FLOPs统计工具下，候选
   部署FLOPs增幅不超过5%；
2. 参数量必须完整报告；参数增幅超过5%的候选仍需单独审批，不能仅凭FLOPs自动进入；
3. RTX 2060上与基线在同一进程、相同会话、相同预热和重复次数下做成对测速；
4. 候选AMP单图中位延迟必须不高于33.33 ms（至少30 FPS）才算满足实时部署；
5. 通用profiler可能漏计`grid_sample`、`unfold`等算子，因此实测延迟优先于理论FLOPs；
6. 精度筛选阈值、验证集选择纪律、三seed要求和测试集封存规则全部不变。

建议测速同时保存FP32/AMP每组原始延迟、均值、中位数、标准差、P95、GPU型号、驱动、
CUDA、PyTorch和代码哈希，禁止跨会话拿两个孤立数字作结论。

## 3. C路线边界

若本提案获批，则新增“C路线：轻量RGB+IR融合机制改进”，候选必须直接替换或增强当前
输入层直接拼接/跨模态融合方式，并同时满足论文依据、作者官方代码、许可证和上述预算。

当前只允许调研候选，不下载实现、不修改网络、不启动训练。B路线ABL的结论不受本提案
影响；本提案也不会自动复活已经失败的DySample/FreqFusion实验。

当前预调研见`docs/ROUTE_C_FUSION_CANDIDATE_SURVEY_2026-07-26.md`；该文件只给出
方向优先级，不构成实现或训练授权。
